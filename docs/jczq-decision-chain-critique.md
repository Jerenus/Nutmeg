# JCZQ 决策链结构性复盘（2026-06-04）

> 这是一份**批判性设计复盘**，不是规则补丁。目的是回答四个问题：
> ① 决策链有没有结构问题？② 有没有逻辑漏洞？③ 想象力是否不足、异常捕捉是否失准？
> ④ **为什么 GPT 和 Claude 跑"同一个任务"会走出不一致的路径，怎么把它系统化。**
> 基于对实际代码（`nutmeg/services/jczq_tiered.py`、`jczq_brief.py`、`jczq_debate.py`、
> `jczq_conflict_*.py`、`scripts/jczq_calibration.py`）和两份 spec
> （`docs/jczq-decision-framework.md` §1-§12 + R1-R28 + A-F + F1-F4；
> `docs/superpowers/specs/2026-05-25-jczq-tiered-plan-design.md` §0-§31）的通读，不是 memory 快照。

---

## 0. 一句话结论

**系统有两个互不共享状态的脑：**

- **代码脑**（`jczq-tiered` v2）：从体彩抓盘 → `v2_candidate_pool` → A/B/D/E 四档 → `recommended_single` → 渲染 brief。**全程确定性、无 LLM 调用、600+ 测试**。给定同一份盘口快照，输出逐字节可复现。
- **散文脑**（`jczq-debate-*` + finalize）：把 brief + "套用 Rule A-J" 丢给 Claude / GPT 各自分析，人再 `debate-compare`、`debate-finalize`。**最有杠杆的那一步——是否信任某个热门、是否覆盖引擎的选腿——发生在这里。**

两脑只靠一份散文 brief 桥接。你感觉"每次都跳出系统、隔离决策"，不是错觉：**确定的部分确实系统化了，但决定胜负的那一步没有，它住在散文里。** GPT/Claude 的不一致是这个结构的必然产物，不是模型脾气问题。

## 0.5 修订：根因在 agent 编排层（2026-06-04 工作流澄清后）

> 下面 §1 最初假设的是"把 brief 贴进另一个 GPT/Claude 窗口"的模型。澄清后发现**真实工作流是
> launchd 定时 + 手动让 agent（Claude Code / GPT）跑 jczq 分析组合任务**。这把根因推得更深，
> 保留 §1 的分析（仍成立），但**真正的病灶是这一节**。

**"任务"是一句自然语言，每个 agent 自己即兴编排。** 你说"让项目进行 jczq 分析组合"，
agent 要自行决定：读哪些 memory、信哪个 CLI、跑 `jczq-tiered` 还是 `jczq-bold-combos`
还是退役的 generator、用哪份 Poisson、怎么 finalize。没有一个**钉死的确定性入口**把"今天的决策"
完整封装起来。于是：

- **Claude Code** 带 `MEMORY.md` + 30 条记忆 + `CLAUDE.md`，倾向按记忆指引走。
- **GPT 系 agent** 记忆/系统提示不同，读仓方式不同，可能跑完全不同的命令甚至不同的引擎。

**两个 agent 在即兴演奏同一句模糊指令 → 必然分叉。** 证据：连项目自己的 memory 都在
`jczq-bold-combos`（"今天的方案"）和 `jczq-tiered`（5/25 起 v2 主路径，¥100/日）之间含糊
——5/25 记忆说 bold 重写成 tiered，但 bold 管线仍在 launchd 跑。**没有单一可信入口，
每个 agent 都在猜该跑什么。这就是"每次跳出系统、隔离决策"的字面机制。**

→ 系统化的真正杠杆 = **一个确定性入口命令 + 一份所有 agent 共读的钉死指令**（见 §6 修订版）。

## 1. 为什么 GPT 与 Claude 路径不一致（先答你最在意的）

分歧**不在引擎**。引擎产物对两个模型逐字节相同。分歧全部来自 finalize/debate 这层判断，原因有四层，从浅到深：

1. **指令指向一个过期标签。** `jczq_brief.py` §6 投递模板写的是
   *"用 Nutmeg 改造版的 jczq 系统对今天进行投资建议（Rule A-J 已落库）"*。
   但真实规则宇宙是 **A-F / R1-R28 / F1-F4 / O-L-H-I-J / §0-§31**，共 38+ 规则标识、28 个章节、1714 行，且**两份 spec 互相矛盾**（见 §2-B）。"Rule A-J" 是个早就对不上的旧标签。模型实际加载了哪些规则，取决于它脑子里恰好浮现什么——这本身就是熵源。

2. **上下文严重不对称（这是最大的单点原因）。** Claude 带着 30+ 条 memory 文件（记得整条 R1-R28 / §14-§31 的演化史、每条规则的 why）；**GPT 是冷启动，只读当天 brief**。两者**根本没在跑同一个任务**——输入的上下文不同，结论不同是数学上的必然，跟"模型不听话"无关。

3. **规则里有真·判断条款。** 不是所有规则都能机械执行，有一批天然要人/模型解读，两种先验必然给出两种答案：
   - F3"≥3 场 ≥+15% alpha **同方向**" —— "同方向" 指同池别？同进球方向？同盘口偏差方向？无定义。
   - §17.1/§29 gap-guard"体彩-欧赔分歧 = **公众造假热门** vs **短赔结构性 margin**" —— 这条线是事后校准出来的，不是演绎出来的。
   - §31 软热"**逐场判断**这场有没有理由打反面" —— 明确要求叙事推理。
   - memory 里的风格指令"**在困难中找落足点、别默认不打、把不利信号翻面读成盘面共识**" —— 这是创作型指令，两个模型执行起来天差地别。

4. **没有机器可校验的单一真相源，且 finalize 被允许覆盖引擎。** memory 记着 5/28"003 强胆 1.30，v2.2 选让平错，Claude finalize 选让负对"——也就是说**最终决策 = 引擎产物 ⊗ 散文脑的自由覆盖**。熵全从这道覆盖口进。引擎本可以是单一真相源，但它的话不算数。

> **要点：** 现在两模型的分歧 **90% 是噪声**（上下文不对称 + 过期标签 + 散文歧义），只有 10% 是真正的"两个分析师看同一份证据、在真模糊处分歧"。系统化的目标 = **把噪声挤干，让剩下的分歧变成信号**（见 §6）。

## 2. 结构性问题

**A. 规则语料是过拟合、累积式的，不是原理式的。**
38+ 规则里绝大多数诞生于"某天输了 → 加一条"（5/11 输→R17，5/14→R22-R25，5/26→§26…）。这是在一个**自认负 EV**（抽水 ~12.5%，§0 明写"无 edge、娱乐"）的游戏里对**单日噪声**做拟合的教科书案例。回测证据本身很弱：memory 记着"过滤腿命中率 27.3% **低于**基线，无误杀"——"没误杀"是很苍白的辩护。§30 是第一次承认这种 churn，但 §25-§29 本身就是 churn，且 §30 **没有回头删除**它们。语料带着大量死重和自相矛盾的条款继续跑。

**B. 两份 spec、两个世界、一个过期标签。**
`jczq-decision-framework.md` 描述的是**已退役的 Poisson generator 时代**（R28 退役 C 票、整个 generator SOP 5/18 退役）。但 brief §6 还在喊"套用 Rule A-J"。模型读到这句话，可能把死掉那一代的逻辑复活。两份文档从没做过合并/裁剪。

**C. 确定性用错了地方。**
代码脑把确定性花在**无关紧要的细节**上（选哪个 3 串、odds band 是 80-300 还是 30-150），却把**真正高杠杆的决策**（信不信这个热门、要不要覆盖）留给散文脑。理想架构正相反：把确定性**往上推到后果最大的决策**，散文只留给真正需要创意的叙事。

**D. 反馈环是开环的，唯一执行器是"人写新规则"。**
校准（§30）和冲突引擎都停在 OBSERVE——只记录、不回灌。所以系统"学习"的唯一通道，就是人在输了之后**再加一条散文规则**——这恰恰是它想停掉的 churn。没有任何机制能说"60-70% 桶系统性高估 → 自动下调该桶权重"。**闭环缺了执行器那一段。**

## 3. 逻辑漏洞

- **规则优先级未定义。** v2.0"高 boldness 就纳入"与 v2.3"poisson edge < -0.15 就排除"**同时激活**，没有声明谁压谁。引擎靠**代码书写顺序**偶然决定，不是靠声明的原则。一条 boldness=0.82 但 edge=-0.18 的腿，命运取决于函数里哪行先跑。
- **R25 符号震荡、无滞回。** §28 把 R25 双向化后，一个赛季漂移的联赛会在残差阈值两侧反复横跳（+0.05 ↔ -0.10），没有 dwell time / 滞回带，系统自己制造抖动。
- **满地魔数 + 事后叙事。** 1.65 / 1.50 / 0.55 / n≥30 / 0.12 / -0.15 / ±0.10 全是事后叙事，不是推导出来的，是被当初产生它们的那几天拟合出来的。
- **§30"别加规则"写在加规则之后。** 它到底是**冻结点**（§25-§29 就此封存）还是**只约束未来**？文档没说清。读者无法判断 v1 generator 是真死了还是还在当 fallback。

## 4. 想象力不足（这条比规则漏洞更值得聊）

- **固定菜单锁死了可表达的想法。** 引擎只会说 A/B/D/E 四档 × {had, hhad, ttg, crs} 四市场。任何超出模板的想法都无法表达：跨场相关性叙事、整个 slate 作为一个 thesis、按对手赛程/动机做的结构判断——都进不来。
- **把"规则增殖"误当成精密。** 真相相反：每加一条规则，**选项空间在收窄**。38 条规则不是 38 分聪明，是 38 道把模型逼回同一个低进球小桶的栅栏（memory 里你自己问过"为什么经常选 0:0"——那正是栅栏共振的结果）。
- **从没认真把"今天不打"当成一个合法输出。** 风格 memory 明确"别默认不打"。但在 6 月初这种**极薄、负 EV、只有零星友谊赛**的盘面（见漏盘教训 memory），"最优解是空仓"是一个**正确**答案，系统却被规训成必须出票。
- **最深的矛盾：序言承认无 edge，规则却假装在抓 edge。** §0 白纸黑字"无 edge、娱乐性质"，但 R1-R28 + Poisson 全套都在演"我在找正期望"。这个分裂没解决，导致系统**既不敢当纯娱乐（一直加规则装严肃），又不可能真有 edge（抽水摆在那）**。真正有想象力的设计应该跳出来问：**如果根本没有 edge，那这套系统的目标函数到底是什么？** 是方差塑形（用小钱买高赔率的情绪体验）？是决策卫生训练？还是盘面阅读的记录工具？目标函数不定，所有规则都是在错误的目标上优化。

## 5. 异常信息捕捉不准

- **漏盘当空盘。** 早场快照不完整 → "0 场" 被误读成空盘（漏盘教训 memory）。系统把一张快照当成完整真相，没有"盘口可能后挂"的不确定性建模。
- **冲突引擎"未对齐"静默丢弃。** value bridge 把 JCZQ 对齐到 API-Football，对不上的（"未对齐"很常见）**直接从冲突分析里消失**。异常恰恰最可能藏在这条对不齐的长尾里，而它是盲区。
- **只抓统计异常，抓不到结构/情境异常。** 系统能算 Poisson edge、gap-guard，但伤停、轮换、天气、死局动机、赛程拥挤——**足球真正最有预测力的信号——一个都不在数据管线里**。模型在散文脑里偶尔脑补这些，但既不可复现也无校验。这是"异常捕捉不准"的真正大头：不是算得不准，是**根本没采集**。

## 6. 怎么系统化（针对 GPT/Claude 不一致，给出可落地的架构）

**原则：分歧不该被消灭，该被净化。** 让两个模型从**完全相同的证据和规则集**出发，只在**真模糊处**分歧——那个分歧本身就是"这场不确定性高"的度量。具体六步：

1. **单一真相源、把规则 inline 进 packet。**
   引擎生成一份 canonical "决策包"，**给两个模型逐字节相同**。不再说"套用 Rule A-J 从记忆里捞"——而是把**今天实际适用的、去重后的、带当前数值的规则**直接内联进 packet。**两个模型都不许依赖自己的记忆**。这一步直接消灭"Claude 有 memory、GPT 没有"的不对称。

2. **分离"确定裁决"与"判断提问"。**
   packet 明说：*"引擎已确定性地定了 X/Y/Z（附 trace）。你只需回答这 N 个真·自由裁量问题：……"*。把模型约束在**真实的裁量面**上，不让它重新审判整个盘。这样两个模型回答的是**同一个有界问题**。

3. **强制结构化输出（schema）。**
   每个模型按固定 schema 返回（match_no, pool, pick, confidence, 一行理由）。`debate-compare` 当前是**正则解析自由文本**（有损）；换成 schema 后是真正的逐项对比。

4. **每条规则二分：能 code 就必须 code，否则显式标 JUDGMENT。**
   审计 38+ 规则。**能写成代码的，必须写成代码**（那它就根本不是 LLM 的决策了，分歧无从产生）。**真需要判断的，标 JUDGMENT 并写清提问 + 模型该权衡的证据**。不允许任何规则停在"模糊中间带"让两个模型各自猜。

5. **把分歧当不确定性信号，降注或排除——而不是当掷硬币。**
   两模型拿到相同 packet **仍**在某场分歧 → 该场标**高不确定性 → 减注或剔除**，而不是从两个叙事里挑一个顺眼的。收敛 → 加信心。**这样两模型设置就从"二选一的赌博"变成了方差估计器。**

6. **版本钉 packet + prompt。**
   两个模型跑的"任务"应是一个**带版本号的工件**（packet vN），让每次运行可复现，也能 A/B 哪个 packet 版本带来更好的校准。

> 注意：这六步**没有一条是在加选腿规则**。它们是在**改变决策边界的位置**——把熵从散文脑挤回代码脑，只把真正不可代码化的判断留给 LLM，并把两模型的分歧从噪声转成信号。这才是 §30"反 churn"该走的方向。

### 6.x 修订：落在 agent 编排层（基于 §0.5）

既然真实工作流是"agent 即兴跑任务"，上面六步要落在这个具体形态上，分三件交付物：

1. **单一确定性入口** `nutmeg jczq-today`（暂名）。
   它内部确定性地：跑 live 引擎（tiered）→ 产出完整决策包 = 票面(A/B/D/E) +
   §-逻辑 trace + 保留的分析底座（热度扫描 / 你常看的 Poisson +EV）+
   **显式列出今天 N 个真·裁量问题**。这是 agent **唯一**需要跑的命令。给定同一份盘口快照，
   输出逐字节可复现——GPT 和 Claude 跑它，拿到的是同一份活的决策包。

2. **一份所有 agent 共读的钉死指令**（`CLAUDE.md` 给 Claude、`AGENTS.md` 给 GPT/Codex，
   内容相同）：*"被要求跑 jczq 每日分析组合时，只跑 `nutmeg jczq-today`，把它的输出当决策；
   不要在退役 generator / 旧 brief / 各份 spec 之间即兴发挥；只在它显式标出的裁量问题上动判断，
   并按 schema 作答。"* —— 两个 agent 读同一份指令 → 同一条路径。

3. **结构化裁量面**：决策包末尾的 N 个裁量问题用固定 schema 作答（match_no/pool/pick/
   confidence/一行理由）。两 agent 在此分歧 → 该场标高不确定 → 减注或剔除（§6.5）。

> 这三件事一起，把"§6 重写 brief"升级成"给整套决策一个确定性入口 + 让所有 agent 共读同一指令"。
> brief 的 §1-§4 分析底座并入决策包（保留），§5 的 generator 死票退出，§6 Rule A-J 模板
> 换成"裁量问题 schema"。**这才是你要的'系统性'——不是更多规则，是一个所有人口径一致的入口。**

## 7. 还不错的地方（保持诚实平衡）

- **§30 的转向是对的。** 用校准日志取代"输一天加一条"，是整条演化史里第一次结构性正确的动作。
- **代码脑是真可复现、真有测试。** 600+ 测试、确定性引擎——这是宝贵的地基，问题不在它，在它之上那层散文覆盖。
- **§0 对"无 edge / 娱乐"的诚实**值得保留——只是要把它**贯彻到目标函数**，而不是一边承认无 edge 一边用规则假装抓 edge。
- **Claude vs GPT 对辩的结构本身是好主意**——前提是按 §6 系统化，否则就是两个不同上下文的模型各说各话。

## 8. 留给讨论的取舍（需要你拍板的开放问题）

1. **目标函数到底是什么？** 方差塑形（情绪体验）/ 决策卫生训练 / 盘面阅读记录 / 还是仍想搏 edge？这一条不定，下面全是空中楼阁。
2. **要不要做一次"大裁剪"？** 把 38+ 规则按 §6.4 二分，砍掉过拟合死重、合并两份 spec、废掉过期的"Rule A-J"标签。代价是承认过去一个月很多规则是 churn。
3. **finalize 还能不能覆盖引擎？** 若能，覆盖必须留 trace 并进校准（覆盖对了吗？）；若不能，引擎就是终审，散文脑只做叙事。
4. **要不要把分歧变成减注信号**（§6.5）——即承认"两模型吵起来的场 = 该少碰的场"，哪怕这意味着更多空仓。
5. **要不要补结构/情境数据**（伤停/动机/赛程），还是接受"只玩盘口数学"并据此调低自我期待。
