# 语料重建让前瞻样本倒退：原因、复原与样本账（2026-10-05）

> 来源：`plans/2026-10-05-research-followups.md` 第 6 条。
> 结论先说：**丢行是真的，而且丢错了**。三类机制（泳道替换、模糊去重误杀、跨日重复）都是语料构建的缺陷，不是「原本就不该算前瞻」。修法是两处去重修正加一本只增不减的样本账；用内核里当时记录的 `inputs_hash` 逐位复原了 7 个历史快照，把丢掉的样本按首次入选时的值找了回来。对结论的影响：F5 37→41、F9 39→45，F9 仍然 ≈ 市场，F10/F11 不变。

## 1. 现象

内核 `rsi_grades` 的累计 n 本应单调不减，实际倒退过两次：

| 实验 | 时刻 | n | 说明 |
|---|---|---|---|
| F9 | 09-25 10:45 → 09-27 10:45 | 8 → 2 | 丢 6 |
| F5 | 09-30 20:31 → 10-01 10:45 | 39 → 37 | 丢 2（净） |

## 2. 复原方法：逐位复原当时的语料

语料在 09-23 → 10-01 之间没有提交过版本，但每次结账的 `inputs_hash`（入选行的 key / actual / fair / belief 摘要）都在内核里。用旧版 `corpus_build.py`（`bce4e9f`）对今天的数据加「当时竞彩赛果封存到哪天、足彩官方赛果到哪期」两个截断重建当时的语料，再跑同一个适配器：**入选集摘要与当时记录逐位相同**，就证明复原的是当时真实的样本。

| 结账时刻 | 竞彩封存到 | 足彩赛果到 | F5 | F9 | 复原 |
|---|---|---|---|---|---|
| 09-25 10:45 | 09-24 | 26131 | 26 | 8 | ✓ ✓ |
| 09-26 10:45 | 09-25 | 26131 | 28 | 8 | ✓ ✓ |
| 09-27 10:45 | 09-25 | 26132 | 28 | 2 | ✓ ✓ |
| 09-28 10:45 | 09-27（09-26 未封存） | 26132 | 29 | 3 | ✓ ✓ |
| 09-29 10:17 | 09-28 | 26132 | 37 | 20 | ✓ ✓ |
| 09-30 15:18 | 09-29 | 26132 | 38 | 25 | ✓ ✓ |
| 10-01 10:45 | 09-30 | 26134 | 37 | 39 | ✓ ✓（F10 17、F11 15 也 ✓） |

截断不是猜的：`official-results.json` 的修改时间是 10-01 10:42，26134 直到那一刻才进；09-26 的竞彩板面 25 场只有 24 场有赛果，回填按「3 天后强封」到 09-29 才封存。

复原不了的：09-22/23 两次（F5 23、24）与 09-30 20:31 那次（F5 39、F9 30）。后者之后 Read 文件被重写过，今天的文件已不是当时的样子。这几个点不入创世，在此点名。

## 3. 丢行机制

### 3.1 泳道替换（主因）——丢错了

同一场比赛同时在竞彩板和足彩期里时，`dedupe` 保留足彩行、丢竞彩行。竞彩赛果第二天早上就封存，足彩要等整期踢完、官方开奖后才进。于是同一场比赛先以竞彩行（竞彩读时盘价格、竞彩 Read 的 belief）入选，几天后被足彩行（足彩 legs-base 价格、足彩判读的 belief）替换：价格带可能翻出去，belief 可能从「拨动」变成「没拨」。

- **F9 的 8→2**：09-24 的竞彩 周四003–008 六场都有拨动过的竞彩 Read（10:00 研究，开球前），26132 结算后被六条 belief=prior 的足彩孪生行替换，六个样本整体消失。
- **F5 丢 3**：09-26 周六014（26133 结算时被替换，价格带外）、09-27 周日002（同）、09-29 周二012（26134 结算时被替换）。同一机制也让 09-28 周一005、09-29 周二008 两场翻进带内——有进有出，所以单看 n 只看到净变化。

两个版本都是开球前的判断，没有哪个「更前瞻」。已经结过账的样本在事后换成另一个来源的值，等于事后改了样本，违反预登记。

### 3.2 延迟封存——不是丢行

09-27、09-28 的 F9 只有 2、3，是因为 09-26 的竞彩赛果到 09-29 才封存（见上），那一天的样本晚到了，不是丢了。

### 3.3 模糊去重误杀——丢错了

没有 titan id 可配对时，`dedupe` 退到「同日三面 fair 差都 ≤1.5pp」就当成同一场。这条规则不看赛果，也不管那条足彩行是否已经被别的竞彩行配走。用今天的数据全量检查，自 7 月以来有 **83 场不同的比赛**被这样丢掉：

| 原因 | 场次 |
|---|---|
| 赛果不同（如 09-19 周六023 主胜 vs 26129-7 客胜） | 69 |
| 足彩行已被另一场竞彩按 titan id 配走（如 09-26 周六018 撞 26132-8，后者已配给 09-25 周五007） | 3 |
| 第二个认领同一条足彩行的竞彩行（一条足彩行只能是一场比赛） | 11 |

83 场里没有一场与认领者 titan id 相同。F5 窗口内受影响的是 09-19 周六002、周六008 两场。

### 3.4 跨日重复——多算了

titan 赛果页按开球历日列场，跨夜场会同时出现在两天的 `jc-results` 里。09-19 周日001（titan 3049657）既在 09-19 页又在 09-20 页，`(日, 竞彩号)` 去重拦不住，同一场比赛从 09-25 起在 F5 里数了两次。全库只此一例。

### 3.5 另查：F9 的 belief 有没有开球后写的

F9 的适配器不检查前瞻证明。逐条核对样本账里 32 个竞彩 F9 成员：Read 的 `made_at` 全部早于开球（其中 09-26 周六006/013/021 三场语料里没有前瞻证明，核对开球时间后分别是 13:55<16:00、01:11<02:00、01:11<08:30）。没有泄漏。

## 4. 修复

1. **去重**（`experiments/corpus_build.py`）
   - 模糊配对要求赛果相同、两边 titan id 不冲突、足彩行没被别人配走；被吸收的竞彩键记在足彩行的 `twin_keys` 上。
   - 同一 titan 场次只留一行，留竞彩号星期与业务日一致的那一行。
   - 内核行的模糊挂接（`attach_kernel`）有同样的毛病：不看赛果，配到已挂了别的内核场次的行时既不挂也不追加。现在要求赛果相同；配到的行已挂内核时，两条内核行的「主 vs 客」简称主客各前两字相同才算同一场的重复身份（丢弃），否则独立追加。找回 48 条（赛果不同 33、队名不同 15，如「贝红星 vs 比尔森」撞上「马赛 vs 斯特拉斯」），同场双身份的 17 条（如「哈尔姆斯塔德 vs 赫根」/「哈尔姆斯 vs 赫根」）照旧丢弃。
   - 结果：语料 1,665 → 1,789 行（+83 场竞彩找回，−1 跨日重复，+48 条内核独立行，6 条原独立内核行改为挂到找回的竞彩行上）。找回的 48 条内核行日期在 07-11 → 08-23，不进任何前瞻实验的窗口，只影响探索性统计；找回的竞彩行里 F5 窗口内有 2 场（见第 5 节）。
2. **样本账**（`nutmeg/decision/rsi_samples.py`，`experiments/rsi-samples.json`）
   - 一场比赛第一次被某实验选中，就把当时的整行冻结为成员；结账 = 冻结成员 + 尚未入账的语料行。
   - 同一场比赛按 titan id / 内核 match_id / 语料键 / `twin_keys` 认身份，孪生行不重复入账。
   - 成员换值（changed）、换泳道（superseded）、消失（missing）、不再被选中（deselected）只记事件，不改样本；同键赛果更正照改并记 `actual_corrected`；语料里同一场出现两次记 `duplicate_in_corpus`、只算一次。
   - 剔除只能由人：`nutmeg rsi samples --exp X --retract <键> --reason … --by …`，剔除后不再入账。
   - `rsi grade` 的前瞻结账都走它（G1 不读语料，除外）；闭环把 `rsi-samples.json` 加进自动提交。
   - `GradeResult` 新增 `selected_keys`，各适配器报出入选行的键，选样逻辑没改。
3. **创世**（`experiments/rsi_samples_genesis.py`，一次性，留作来源证明）：只把第 2 节逐位复原成功的快照按时间顺序入账，`source=genesis`，`proof=结账时刻:摘要前缀`。创世成员：F5 39、F9 45、F10 17、F11 15。之后的入账走正常结账路径。

## 5. 对读数的影响

用今天的数据与修正后的语料，按样本账结账（下一次 10:45 闭环会得到同样的数）：

| 实验 | 修前 | 修后 | 变化来源 |
|---|---|---|---|
| F5 | n=37，+12.26pp，CI [−3.9, +28.4] | n=41，+14.29pp，CI [−0.7, +28.9] | +3 泳道替换找回、+2 误杀找回、−1 跨日重复 |
| F9 | n=39，−0.21pp，CI [−0.9, +0.6] | n=45，−0.29pp，CI [−1.1, +0.6] | +6（09-24 竞彩六场） |
| F10 | n=17，+19.53pp，CI [+1.8, +32.5] | n=17，+19.53pp，CI [+1.4, +32.6] | 无（CI 微动是行序变了，bootstrap 抽样不同） |
| F11 | n=15，−14.08pp | n=15，−14.08pp | 无 |
| F13/F14/F15/K1 | 0 | 0 | — |

结论没有变：F9 仍然 ≈ 市场（CI 含 0）。F5 登记的主张是「价格带 [10,20) 的模态面开出率低于价格期望约 8pp」，前瞻读数是 +14pp，方向相反；证伪判据是 n≥120 时 CI 下界 > −2pp，目前下界 −0.7pp，再攒到 n_min 若维持就会被证伪。

首轮结账会记下 F5 9 条、F9 16 条 `superseded` 事件，都是 3.1 节的泳道替换，样本仍按首次入选的值计。

## 6. 剩下的风险

- 冻结意味着首次入选时的错值也会被保留。如果事后发现某个成员本不该算（例如 Read 晚于开球），只能由人带理由 retract。
- 创世没复原的 09-30 20:31 那次（F5 多 2 行、F9 多 5 行）找不回来了。语料从 10-01 起每天提交，以后同类问题可以直接 diff 版本。
- `twin_keys` 只在本次修正后的语料里有；早于修正冻结的足彩成员行没有这个字段，不影响身份识别（titan id 仍在）。

## 7. 复核方式

```bash
uv run python experiments/rsi_samples_genesis.py --out /tmp/genesis.json   # 逐快照打印「复原 ✓」
uv run nutmeg rsi samples                    # 各实验成员数与事件
uv run nutmeg rsi samples --exp F9           # 最近 20 条事件
uv run pytest tests/decision/test_rsi_samples.py tests/experiments/test_corpus_build.py -q
```

注意：创世复原依赖今天的数据文件，若之后 Read 等文件再被重写，重跑可能对不上——这正是要冻结的原因；当时的入账以提交进仓的 `experiments/rsi-samples.json` 为准。
