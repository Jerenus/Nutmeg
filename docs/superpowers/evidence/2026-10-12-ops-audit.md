## §3 三处缺陷与根因

### §3.1 F9 天平义务对重叠场永不履行（rsi.sweep 每小时红）

- 现象：`rsi.sweep.err.log` 自 9 月起 107 条 `DUTY_NOT_FULFILLED`（F9 为主，另有 R0/F1c/F2/F5 历史）；10-10 丢 11、10-11 丢 2、10-12 丢 8。09-30 项目评审已记「F9 balance-ledger 9 条未查根因」。
- 根因（内核直查验证）：并集日里竞彩/足彩重叠的场在内核有**两个 Match id**——足彩 `<期>-store-ids.json` 一套（如 考文垂-纽卡斯 场3 = `match-6696caba…`）、竞彩 legs-base 一套（周一007 = `match-5aa083a7…`）。F9 duty 行经 `_keep_scheduled_identity` 按足彩 id 排；`rsi balance` 组 rows 时要求 `read_by_match.get(match_id)` 且 `match_id in kickoffs`，而 Read 落在竞彩 id 上 → 重叠 8 场没有 row → 永不 fulfill。今天 16 条义务只履行 8 条，未履行的 8 条正是 26139 场 3/4/5/6/7/8/10/14。
- 后果：前瞻样本按宪法不可补，F9 的 n 与 gaps 失真；sweep 的 `failed` 计数把「未履行」与「命令失败」混在一起，状态条常红导致真失败也看不出。
- 修法：组 rows 时用 channel-map 把竞彩 Read 映射到足彩身份（或反向），不改早退分支。

### §3.2 10-10 板腰斩场卡住封存

- 周六006 巴列卡诺-毕尔巴鄂 10-10 中止，`jc-results` 29/30 永不齐；`jczq/void-matches.json` 注明「来源：赛后人工确认」，没人填就不封存。
- 后果：10-10 改判账、回放样本未结；backfill 每次 exit 2，`day run --job results` 每次 exit 1。
- 修法：作废场自动识别（体彩接口状态）+ 本期人工补录。

### §3.3 plist `;` 串联吞退出码

`day.settle` / `jczq.research` / `day.verdict` / `day.brief` 四份 plist 用 `;` 串多条命令，launchctl 只记最后一段；`ops-status` 14 行有 11 行「无标记」（只有 account.month / ops.deadcode / decision.am 打 NUTMEG_OK）。`/runs` 只读 `job=="settle"` 行（`day_runs.py:82`），`_verdict_runs` 恒报 ok（`day_runs.py:270`），`_research` 以文件 mtime 判成功。
