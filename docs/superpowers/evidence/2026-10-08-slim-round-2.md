# 第二轮瘦身（2026-10-08）

> 起因：Jun 2026-10-08 问「能否用更少更精简的代码完成同样的工作过程和思考链路」，以及 AOCI 索引该先建还是后建。
> 结论：先改造、后索引；改造按 A（死代码）/ B（单一来源）/ C（规则与提示词层）/ D（三项待决）执行。
> Jun 授权原话：「先完成 ABC；D：迁移链两段一次性修复、通知出站队列重写、先确认 ledger_writeback 是否有用——
> 没用或不在最终设计中就删，是设计一环就找到问题并修复。」计划已执行后删除（plans/ 只放未完成；原文见提交 `deda3cc`）。

## 1. 方法

- 四个只读审计代理分区（内核 / 决策链 / CLI·产品·数据 / 测试·脚本·提示词），「死」的判定从现役入口出发：
  launchd plist、`day_runner` / `rsi_loop` 步骤表、列表式子命令派发、`rsi_duties` 观测仪、OpenClaw cron、RUNBOOK；
  只被测试引用＝生产上已死。每条结论都附 grep 证据，主会话抽查后才采用。
- 五个工程代理在各自 worktree 并行开发（K 内核 / P 产品·网页·配置·脚本 / B 决策层 / N 通知 / C 规则与提示词），
  按目录划分归属；主会话逐个合入 `slim-r2`，每次合入跑 ruff、导入检查（含函数内延迟导入）与全量 pytest。
- 行为改变一律在生产数据的沙盒副本上做改前改后对比，数字写进各自提交信息。
