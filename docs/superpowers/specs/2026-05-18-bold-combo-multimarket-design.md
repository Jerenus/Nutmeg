# 大胆引擎多市场扩展 — 设计文档

- **日期**：2026-05-18
- **状态**：设计待用户评审
- **一句话**：把大胆引擎从「只吃胜平负」扩到 **胜平负 + 让球 + 总进球 + 比分** 四个市场，薄盘日也能拼出跨市场的高赔大胆串。**仍是娱乐工具：不预测胜负、无 edge、长期负期望。**
- **前置**：`2026-05-18-bold-combo-engine-design.md`（v1，已交付）。本文是其 §8「后续扩展」的落地。

---

## 0. 诚实声明（焊死，沿用 v1）

本扩展不改变 v1 的诚实定位。每个输出顶部硬标签不变：
> 🎲 娱乐性质 · 非 edge · 长期约 −13% 抽水期望 · 仅用娱乐预算下注

新引入的「盘口内部一致性冲突分」是**启发式显著性分，不是概率**。产品任何地方不得出现「胜率 / edge / +EV / 正期望 / 推荐下注 / 重仓」。

## 1. 背景

v1 大胆引擎只做胜平负。薄盘日（如 2026-05-18 只有 3 场）→ 3串1 只有唯一一种组合，创造力无从谈起。真正的高赔大胆藏在 让球/总进球/比分 —— v1 §8 当时划到范围外，现在落地。

**数据现实（2026-05-17 recon `docs/superpowers/notes/fcom500-page-structure.md` §4 定版结论）**：500.com 静态页面**只有胜平负有干净的国际欧赔**。让球的国际亚盘是 2-way、结构不同；进球指数页只有体彩自己的行；比分赔率由 JS 动态加载、静态页里完全没有。所以**让球/比分拿不到外部国际欧赔** —— 本设计用「盘口内部一致性」取代，它不需要外部依赖，且正中「寻找盘面冲突点」的初衷。

## 2. 它做什么

**四个市场**：had（胜平负）、hhad（让球胜平负，带让球线）、ttg（总进球 exact count 0–7+）、crs（比分）。hafu（半全场）不纳入。

**三个数据源**（均无 API 配额）：

| 数据 | 来源 | 用途 |
|---|---|---|
| **完整体彩盘** had/hhad/ttg/crs 全部报价 | Sporttery 官方 API `getMatchCalculatorV1`（context.json 的 `source_api`） | 所有市场的体彩隐含概率 + 内部一致性冲突 |
| 国际欧赔（胜平负） | `Fcom500` `parse_european_1x2`（现成） | 胜平负外部冲突/漂移/离散 |
| 国际大小球 over/under | `Fcom500` **新增** `parse_over_under`（daxiao 页，fixture 已录） | 总进球外部冲突 |

> ⚠️ v1 引擎读 context.json 里**精选过的** `candidates`（ttg 仅 5/8 桶、crs 仅 ~10 个比分）。内部一致性聚合需要**完整盘**，所以本扩展改读 Sporttery API 返回的完整每池报价。replay 历史日期须用持久化的完整盘快照，不重新抓取（否则回放会拿到今天的赔率）。

流程：① 每场每市场每选项算大胆分（§3）→ ② 全天聚合 0–100 混乱值（§3.5）→ ③ 每场每市场选大胆腿、跨市场拼 3/4/5 串（§4）→ ④ 1 张稳健底仓 + 一组大胆票 + 顶部硬标签（§5）。

## 3. 大胆分（按市场）

| 市场 | 冲突分 | 反直觉/长尾分 | 热度分 | 漂移分 | 离散分 |
|---|---|---|---|---|---|
| **胜平负 had** | 外部：体彩 vs 国际欧赔 | ✓ | ✓ | ✓ 欧赔初赔→即时 | ✓ 国际欧赔逐家 |
| **让球 hhad** | 内部：体彩 vs crs 聚合 | ✓ | ✓ | — | — |
| **总进球 ttg** | 内部：体彩 vs crs 聚合 ＋ 外部：体彩 vs 国际大小球 | ✓ | ✓ | — | ✓ 国际大小球逐家 |
| **比分 crs** | 内部：继承所属 had / ttg 桶的冲突 | ✓ | ✓ | — | — |

胜平负的 5 信号沿用 v1，不变。新内容：

**🆕 盘口内部一致性冲突分**：体彩对同一场报 4 个市场，它们不是独立的 —— 都是同一场底层结果分布的不同切面。比分（crs）最细，其余市场都是比分分布的确定性聚合：
- crs → had：`P(主胜)=Σ_{h>a}P(h:a)`、`P(平)=Σ_{h=a}`、`P(负)=Σ_{h<a}`。
- crs → ttg：`P(总进球=k)=Σ_{h+a=k}P(h:a)`。
- crs → hhad（让球线 L）：`P(让主胜)=Σ_{h−L>a}P(h:a)` 等。

把体彩 crs 盘 de-vig 成比分分布、聚合出**推导值**，与体彩**直接报价**的同选项隐含概率比：
`内部冲突[市场][选项] = |体彩直接报价隐含概率 − crs聚合推导隐含概率|`，clip[0,1]。

- **crs→had 聚合干净**：体彩 crs 盘的「胜其他/平其他/负其他」桶有明确主/平/客归属，全部计入。
- **crs→ttg 聚合近似**：仅对显式报价的 exact 比分求和，「其他」桶不计 —— 诚实标注为近似。
- **crs 腿自身**的内部冲突 = 它所属 had 桶与 ttg 桶冲突分的较大值（最细市场无更细可比）。

**🆕 总进球外部冲突分**：体彩 ttg exact-count 分布在大小球线（如 2.5）上聚合出 `P(大球)=Σ_{k≥线}P(ttg=k)`，与国际大小球（daxiao）同线 fair prob 比，取绝对差。

**长尾/反直觉分**：`1 − 体彩隐含概率`（v1 的 `contrarian_score` 公式，天然泛化到 ttg/crs 的多选项 —— 越冷的比分/进球数分越高）。**热度分**：场级标量，沿用 v1。

**跨市场可比性（关键）**：各市场活跃信号数不同（had 5 个、ttg 4 个、hhad/crs 3 个）。若等权求和，信号多的市场大胆分系统性偏高、候选池被 had 垄断 —— 与跨市场目标相悖。**规则**：每条腿的大胆分 = 该市场**活跃信号**的加权和，权重**按市场归一化**（活跃信号权重和恒为 1，缺席信号不占权重）。这样 had/hhad/ttg/crs 的大胆分同尺度可比。

> 诚实边界：ttg/crs 的冲突主要来自体彩盘自身不自洽（内部），不是市场分歧。理由串写「盘口内部冲突」「长尾冷门」，**不伪造成「市场分歧」**。

## 3.5 全天大盘面混乱值

沿用 v1：每场「离散分 + 冲突分」均值得不确定度，全天中位数 → 0–100 混乱值，调制候选池 `N` 与组合长度。现在聚合的腿更多（跨 4 市场），口径不变。

## 4. 选腿 + 跨市场组合

- **候选腿**：每场每市场取该市场大胆分最高的选项 → 一条 `BoldLeg`（带 `market` 字段）。一场最多贡献 4 条腿。
- **候选池 `N`**：由混乱值驱动（v1 不变），从全部候选腿里取大胆分 top-N。
- **组合**：3/4/5 串 1，**每场最多一条腿**（Rule O —— 一票内同场禁混玩法；不同场的腿可来自不同市场）。按「合计赔率 × 平均大胆分」排序。
- **跨市场创造力**：一张 3 串可以是 A 场比分 + B 场总进球 + C 场让球 —— 合法、高赔、有想象力。

## 5. 输出

- 沿用 v1：1 张稳健底仓 + 一组大胆票，顶部焊死硬标签 + 当天混乱值。
- **稳健底仓**保持**胜平负-only**（「取最低赔热门对冲」只有胜平负有这概念），诚实标注不变。
- **大胆票**每条腿新增 **市场标签**（胜平负/让球/总进球/比分）+ 选项 + 体彩赔率 + 大胆理由（注明主导信号）。
- 所有票无胜率/EV 字段，沿用 v1。

## 6. 落地

- 修改 `nutmeg/data/fcom500.py`：新增 `parse_over_under`（daxiao 页 → 国际大小球 over/under fair prob + 逐家 odds + 大小球线）。
- 修改 `nutmeg/services/jczq_bold_combos.py`：完整盘加载器（读 Sporttery `getMatchCalculatorV1` 完整每池报价）、`internal_conflict`、`external_conflict_ttg`、`BoldLeg` 加 `market` 字段、`boldness` 按市场分派、跨市场组合生成。
- 完整盘持久化：context.json（或并列快照）存完整每池报价，replay 读快照不重抓。旧 context.json 无此字段 → 优雅降级（退回 v1 胜平负-only）。
- CLI `jczq-bold-combos` 复用（`--date`/`--replay`/`--write`），输出多市场。
- 复用既有 PDF 渲染 + Telegram 推送。

## 7. 验收

- 输出含 🎲 硬标签、不含优势措辞、引擎不 import 任何预测模型 —— v1 三条硬约束测试断言全部沿用。
- `parse_over_under` TDD（对录制的 daxiao fixture）—— 返回大小球线 + over/under fair prob + 逐家 odds。
- 内部一致性冲突分对合成的完整盘有确定性断言（crs 聚合 → had/ttg/hhad）。
- 生成的跨市场 3/4/5 串每张守 Rule O（每场 ≤ 1 腿）—— 测试断言。
- 引擎读完整盘；context.json 无完整盘字段时降级到胜平负-only 不崩 —— 测试断言。
- TDD；全量 `uv run pytest tests/` 绿。

## 8. 范围外

- **比分/进球数的国际欧赔**：500.com 静态页拿不到（recon §4 定版），不接；不为此引入 headless 浏览器，也不动用 API-Football（重新消耗配额、偏门联赛覆盖不稳）。
- hafu（半全场）不纳入。
- 不做胜负预测、不做模型校准、不引入球队战绩/xG/H2H。
- 不号称 edge、不承诺盈利。

## 9. 成功标准

薄盘日也能给出**跨市场、有想象力的高赔大胆串** —— 从真实盘面信号（外部市场分歧 + 盘口内部不自洽 + 长尾 + 热度）挑腿，而非乱押冷门；同时全程对「它是什么」诚实（焊死硬标签、禁优势措辞、不报伪胜率、内部冲突不伪装成市场分歧）。

## 10. 后续修订（2026-05-18 落地后 live 跑暴露）

多市场版首次真实运行暴露两处粗糙，本节修订：

**10.1 返奖封顶感知** —— 竞彩单注（一张彩票）返奖封顶 **500 万元**（`JCZQ_PAYOUT_CAP_YUAN`，具名可调常量）。参考注金 2 元/注（`REFERENCE_STAKE_YUAN`）→ **有效赔率上限 = 500 万 ÷ 2 = 250 万×**。组合排序从「合计赔率 × 平均大胆分」改为「**有效赔率** `min(合计赔率, 上限)` × 平均大胆分」—— 超封顶组合的有效赔率到顶不再加分，引擎不再追千万级的无效赔率。`total_odds` 字段仍存真实赔率乘积（不篡改），但超封顶的票渲染时**诚实标注**：「本票 2 元理论赔付 X 元 · 超 500 万单票封顶 · 实际兑至 500 万」。不静默截断、不隐藏。

**10.2 单票市场混搭** —— `MAX_LEGS_PER_MARKET_PER_TICKET = 2`：一张大胆票里同一市场最多 2 条腿。3 串 1 不能三条全比分，必须含 ≥1 个别市场 —— 跨市场创造力落到每一张票上。组合生成器拒掉超限组合。**仅当候选池跨 ≥2 个市场时启用**：单市场日（如 v1 胜平负-only，或某天只有胜平负赔率）该约束不触发，否则会把仅有的票全毙掉。稳健底仓由 `anchor_ticket` 单独生成（胜平负-only，§5），不受本约束影响。

## 11. 后续修订 II（GPT 当日分析对比触发，2026-05-18）

对比 Codex/GPT 当日 `debate/gpt-analysis.md`，暴露两处（GPT 方案本身跑在已退役的 Poisson/conflict-engine 栈上、不采纳，但它的两个观察成立）：

**11.1 无胜平负的场被整场丢弃** —— `bold_matches_from_sporttery` 当前要求 had 有 3 个报价，否则 `continue` 跳过整场。但多市场引擎里 让球/总进球/比分 **不依赖胜平负** —— 体彩对强弱悬殊场（如阿森纳 vs 伯恩利）常先开让球盘、胜平负留空（had `None`）。这等于因为缺一个市场丢掉一整场的另外三个市场。**修正**：只要 had/hhad/ttg/crs **任一盘**有可用报价就加载该场；had 缺失时该场不产胜平负腿、不进稳健底仓（底仓本就 had-only、`anchor_ticket` 自然跳过无 had 的场），让球/总进球/比分 照常产腿。

**11.2 跨票集中度** —— 多张大胆票可能共享同几场 → 它们一起赢一起输，并非真分散（GPT 称之为「集中度红区」）。**修正**：① 组合选取从「按有效排序分取 top-N」改为**多样性惩罚贪心** —— 每个候选组合的有效排序分 `÷ (1 + CONCENTRATION_PENALTY × 已入选票中其各腿场次的累计出现次数)`，盘子有备选时自动把票摊到更多场次；薄盘日无备选则退化为原排序（不破坏薄盘日出票）。② 渲染层加跨票集中度提示：某场出现在 >60% 的大胆票时，顶部 🟦 警示点名该场。③ 底部注金提示加一句：多张票相互独立 ≠ 风险分散，可只挑一张、或一张都不买。这三点是**诚实地暴露集中度**，不做家长式硬过滤。

## 12. 后续修订 III（§11.1 加场后暴露的「比分结构性垄断」，2026-05-18）

修 §11.1（加载无胜平负的场、阿森纳进来）后重跑，4 张大胆票**全变比分** —— §10.2 的单票市场上限被绕过。根因在**候选池层**：候选池 `_match_diverse_pool` 按「每场最大胆腿」播种，而冷比分的反直觉/长尾分 ≈ 1.0、**比分腿的大胆分结构性碾压其他市场** → 池子被比分填满 → §10.2「池子跨 ≥2 市场才启用上限」的判定把全比分池误判成单市场日 → 单票上限不触发。前两次（v2→§10）的「修好」实为侥幸：那天池子恰好混了市场。

**修正**：候选池构造改为 `_balanced_pool` —— **市场均衡播种**：任一市场在池中最多占 `pool_n // 2` 个名额（`MARKET_POOL_SHARE` 口径）。先按「每场一条腿、且该市场未超额」播种（场次覆盖 + 市场覆盖并重；某场最大胆腿的市场已满则取其次大胆腿），再按全局大胆分补满剩余名额。这样只要当天存在 ≥2 个市场，池子就必然跨 ≥2 市场，§10.2 的单票上限才真正生效、大胆票稳定跨市场混搭。真正只有单一市场的日子（v1 胜平负-only）退化为单市场池，§10.2 自然不触发、照常出票。`_match_diverse_pool` 由 `_balanced_pool` 取代。

## 13. 后续修订 IV（切合实际的目标赔率，2026-05-18）

用户指出多市场版产出的大胆票不切实际 —— 单票 9 万×–1600 万×，等于买彩票。根因：大胆分奖励**最冷的选项** → 引擎每次挑 freak 比分（800×）、总进球 7+（23×）→ 三条相乘炸到天上。「大胆」被推到了荒诞。

**修正**：大胆票瞄准一个**切合实际的目标赔率区间**，不再瞄准最大。

- **目标区间**：3 串 1 约 **80–400×**（用户选定）。更长的串按 `fold / 3` 指数缩放（4 串 ≈ 280–2400×、5 串 ≈ 1500–2 万×）—— 单腿赔率维持现实区间不变，串越长自然越高。常量 `TARGET_ODDS_3FOLD_LOW = 80`、`TARGET_ODDS_3FOLD_HIGH = 400`。
- **单腿赔率区间**：`LEG_ODDS_MIN = 3.0`、`LEG_ODDS_MAX = 9.0`。`bold_leg_for_market` 在该区间内挑最大胆的腿（腿是「明确冷门」不是「freak 怪球」）；某场该区间内无可选时退回全体最大胆腿（兜底，真实数据极少触发——每场总进球 2/3/4 球都在区间内）。
- **组合排序**：`_ticket_rank_score` 从「有效赔率 × 大胆分」改为「`_band_fit(总赔率, fold)` × 大胆分」。`_band_fit` 在目标带内为 1.0、带外按比率衰减 —— moonshot 组合的排序分被打到极低，选不进票面。
- §10 的返奖封顶诚实标注**保留**作兜底；目标带在 80–400×，正常不再触发。`bold_leg`（v1 胜平负-only 函数）不受影响。

## 14. 后续修订 V（欧赔快照可复现，2026-05-19）

2026-05-18 复盘把 bold 引擎首次回放（`uv run nutmeg jczq-bold-combos --replay 2026-05-18`）暴露一处隐性失真：输出的**大盘面混乱值 0/100**，conflict / drift / dispersion 三个信号全为 0 —— 而当天 brief 明确显示 500.com 欧赔 4/4 场对齐 100%。根因在 `run_bold_combos_multimarket`：国际 odds（`collect_bold_odds`）只在 `replay=False` 分支抓取，且**从不持久化**。`replay=True` 时 `bold_odds` 恒为 `{}` → 5 个信号只剩 heat + contrarian 2 个 → 回放出来的方案是「跛脚引擎」的方案。**每一次回测 / 复盘都在用一个残缺引擎**，回测结论本身不可信。

**修正**：国际 odds 与 Sporttery 完整盘一样落日级快照。

- **live 跑**（`replay=False`）：`collect_bold_odds` 成功后，`persist_bold_odds_snapshot` 把结果写 `daily/<date>/bold_odds.json`。每个 `MarketOdds`（`nutmeg.data.fcom500`，纯 dataclass、无预测模型）经 `dataclasses.asdict` 序列化为纯 dict —— odds / fair_probability / independent / line / bookmaker_count / opening_odds / per_book_odds 全是 JSON 原生类型。
- **replay 跑**（`replay=True`）：`load_bold_odds_snapshot` 读回快照、用 `MarketOdds(**d)` 重建对象填进 `bold_odds`；再交给 `bold_matches_from_sporttery` 走原有富集路径。
- **快照缺失**（5/18 及更早的日期从未存过）→ `load_bold_odds_snapshot` 返回 `{}`，优雅降级体彩-only，与现状一致、绝不崩。5/19 起的 live 跑会带快照，回放从此完整复现。
- `MarketOdds` 是 `nutmeg.data.fcom500` 既有 dataclass，引擎已在 `euro_from_fcom500` / `replay_bold_combos` import 它 —— 不新增对预测模型的依赖，§7 三条硬约束不动。

验收：`MarketOdds` → dict → `MarketOdds` 往返相等；replay 读到快照后 conflict 信号非 0（混乱值不再恒 0）；快照缺失返回 `{}` 不崩；TDD，全量 `pytest` 绿。

## 15. 后续修订 VI（主题剧本票，2026-05-19）

2026-05-18 回测暴露：5 张大胆票实为**同几条腿的排列**（4 张共用 002 比分 1:2 + 001 比分 2:1），让球腿系统性全是「让平」，票面毫无性格。根因：薄盘日候选腿少，`bold_combos` 的多样性惩罚贪心退化为原排序 → 每张票都奔同一批最高分腿。bold 引擎卖的是「想象力」，5 张同质票把想象力清零。

**修正**：把「大胆票 1-5」从「排序分 top-N」改为**一票一主题**，每张票一个剧本原型 + 一句剧本叙事。

- **5 个主题原型**（按腿构成事后归类，描述性、不改选腿、不与 §10.2 跨市场上限冲突）：
  - **平局收割** —— 平局向腿（胜平负平 / 让球让平 / 比分平局）占多数
  - **冷门比分梦** —— 比分腿占多数
  - **黑马让球** —— 让球腿占多数
  - **进球狂欢** —— 总进球腿占多数
  - **全市场混搭** —— 跨市场无单一主导（含胜平负主导的兜底情形）
  - 归类优先级：平局向多数 → 平局收割；否则单一市场过半 → 该市场主题；否则 → 全市场混搭。
- **一票一主题选取**：`bold_combos` 把 3/4/5 串的全部合法组合（守 Rule O + §10.2）汇成一池，逐个归类；再按主题固定顺序，每个主题取该主题内排序分（`_band_fit × 大胆分`）最高的一张，仍用集中度惩罚做同分摊派。某主题当天无组合 → 跳过（薄盘日**诚实地少出几张**，不硬凑 5 张雷同票）。一票一主题天然低重合 —— 平局收割票与进球狂欢票几乎不可能共腿。
- **chaos 的角色**：仍由 `chaos_pool_size` 驱动候选池大小（「娱乐抖动旋钮」照转）；组合长度不再由 `_fold_weights` 硬性配额决定，而是随主题自然浮现 —— §3.5 的「混乱→更长更野」改由主题多样性表达。
- **剧本叙事**：每张票渲染时票头带主题名（`### 大胆票1 · 冷门比分梦（…）`），票下加一行 `> 剧本：…`。叙事是纯娱乐 flavour，**不含任何优势措辞**（沿用 banned 词表 胜率 / edge / +EV / 正期望 / 推荐下注 / 重仓 断言）。

验收：主题归类对 fixture 确定；同一主题不重复出票、不同票主题各异；渲染含主题名 + 剧本行；输出无 banned 词（§7 沿用）；薄盘日组合不足时少于 5 张不崩；TDD，全量 `pytest` 绿。
