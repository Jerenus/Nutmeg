# 足彩完整 SOP 入口

在 Nutmeg 仓库根目录操作。权威正文保留在现有文件，不在本技能复制规则。

1. 读取 `AGENTS.md`、`docs/sop/{CONSTITUTION,RUNBOOK,RULEBOOK}.md`、`docs/research/INDEX.md`，再核 `.nutmeg-data/daily/<日>/session.md`、`decisions.json` 及本期真实产物。恢复任务不能把旧回执当完成证明。
2. 按 RUNBOOK 泳道 B 执行。**逐场研究到齐不等于完整 SOP 或分析包完成。** B4 转录、B5 初判和机器初稿、B5e 阅读层均保留；预算未获回答仍推进独立研究，不自行设为已承诺预算。
3. 分析包和“做成页面”必须读取 `.claude/commands/zucai-packet.md` 全文。沿用同一包和同一页，保留 §0、14行决策表、全部现行分板块统计/反证矩阵、胆表、主形与替代及固定参考形、死法清单、14场取证附录；同时写 `packet.json`。页面请求不把原任务缩成复制研究摘要。
4. 缺报价或链路失败：查真实来源，记录逐场原因，继续无依赖步骤。未知不算未价；三场缺价不能拿其余十一场冒充整期板型、14场初稿或完整概率。只用受支持来源；不为完成检查硬凑事实、许可或概率。
5. 交付前执行 `uv run nutmeg judgment packet-check --issue <期>`，并读回现有报告页，人工核对分表与旁车、该阶段已有的审票回执、来源时间和证据。输入不足的票形保留槽位和原因，不为通过检查补值；用户未给草案时不要求桥的回执。检查只验证核心产物结构，不决定投注，也不证明事实正确。未通过时列具体缺口并保留阶段状态。
6. 用原有项目状态文件保存检查点。分别说明：已执行的分析、待外部数据、待用户预算/草案、售日复核和赛后复盘。B桥须用户草案，实购/外发按现有授权；不得替用户签字或把未来阶段记成完成。

## 终稿验收与交付

用户要求完整 SOP 时，逐步推进是内部执行方式，不是允许逐段交差。研究摘要、条件参考、修复回执和已更新页面都不能替代终稿。**有可独立推进的步骤就继续执行，不以“已有一页”结束任务。**

赛前分析包终稿须同时满足：
- 本期14场身份与合格市场输入齐备；研究、B4转录与投影已核验，B5完整初判/初稿已实际生成。
- B5e现行全部分表、14场取证与反证矩阵、逐条件许可、主形/替代/固定参考形及适用审票算术齐备；实际未知明确写未知，不把未知凑成许可。默认空仓也是有效结论，但不豁免参考算术和规定表格。
- 用户期前预算已按现役SOP确认；未答只问必要问题，不擅自承诺。用户草案未提供不虚构桥/实购回执。
- 新鲜 `judgment packet-check` 无缺项；另逐项人工核验内容、数据时间、统计口径、审算和原页面读回。结构检查通过只是必要条件，不能单凭文件存在宣布完成。
- 在本期交接记录写明每项证据位置、验收时间与结论，再按B5e交付同一页链接。只说“赛前分析包完成”；售日复核、用户桥/实购和赛后复盘依真实时点分别验收，不能提前称全生命周期完成。

**任何一项未满足，不发送终稿交付回复。** 保持任务未完成：可以继续的立刻做；确需外部数据或用户输入时，仅发阻塞通知（缺什么、已查到什么、下一步/恢复条件），保存检查点。草稿可内部落盘并更新原页，但不主动把草稿链接包装为本次交付；用户主动索要进度或草稿时清楚标明未验收。没有已启动的监控/任务，不声称会后台持续推进。

附最近停售及剩余分钟，未定默认空仓。
